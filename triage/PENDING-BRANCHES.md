## 進め方

- **PR の枠**: 新しい PR は、開いている PR がマージされるたびに 1 本ずつ出す（利用者の指示 11-14）。利用者が本数を指示したときはそれに従う。出す前に最新の master に rebase し、そのブランチのテストを流し直す。`Fixes #N` のあるバグ修正を先に出す。本数に合わせるための修正はしない（利用者の指示 11-20、意味のある修正だけ）。
- **出す順**: まず積んだブランチの土台（利用者の指示 11-16: Issue の有無に関係なく、積みが 1 本になるまで土台を先に出す）→ Fixes の付いた `feat/`（表の順）→ Issue のないもの。テストだけの PR はそのあと（`Closes` の付くものが先）。**最後**は、Issue が先に閉じられて `Closes` を付けないテスト 4 本（`test/refresh-token-drift`・`test/ngax-first-visit-login`・`test/recreate-missing-passphrase` は利用者の指示 11-25: 出すが後回し。`test/list-and-indexes-verification` は #1809 が 11-25 に閉じたので同じ扱いにした）。サーバーと ngclient の対はサーバー側を先に出す。
- **積んだブランチ**: `ci/shellcheck-extensionless-scripts` が `ci/shellcheck-warning-severity`（#8056）の上。#8056 のマージ後に master へ rebase して出す（同じ行を変えるので先に出すと衝突する）。
- **`codex/` のブランチ**: ngclient 側のセッション（Codex）が作ったもの（今はなし）。rebase と push は Claude のブランチと同じに扱うが、マージ済みのブランチを消すときに**誤って消さない**（利用者の指示 11-18）。マージされたら、PR の状態を確かめてから消す。
- **triage の更新手順**: `jj new triage` → node のスクリプトで編集 → `jj squash -m "Add triage notes"` → `jj bookmark set triage -r '@-'` → `jj git push --remote origin -b triage` → `jj new master@upstream`。triage は 1 コミットのまま保つ。
