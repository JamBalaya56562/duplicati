# #7517 への質問の下書き（2026-11-12、186、投稿済み: https://github.com/duplicati/duplicati/issues/7517#issuecomment-6818524688）

The error comes from Jottacloud, through the Duplicati OAuth service: when the service tries to refresh the token for this AuthID, Jottacloud answers `invalid_grant` / `Session doesn't have required client`. That usually means the login session behind that AuthID is no longer valid.

I think the restore may not be using the new AuthID. The OAuth service keeps the access token for an AuthID for about as long as it is valid, so right after a successful "Test connection" the same AuthID should get that token again without a new refresh. A refresh that fails right after the test points to a different AuthID, for example the old one.

Could you check these?

1. Did you save the backup after you changed the AuthID, and did you start the restore from that backup (not with "Direct restore from backup files" and the old URL)?
2. Does a backup of the same job work, or does it fail with the same error?
3. Is the AuthID also set somewhere else, for example as `--authid` in the advanced options or in a command line script?

If the restore still fails with the new AuthID, it would help to know how long after the test connection the restore was started.
