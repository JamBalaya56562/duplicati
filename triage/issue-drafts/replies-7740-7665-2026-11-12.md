## #7740

#7753 is merged and should be in the next canary. It does not fix the missing `System.IO.Compression`, but the service will no longer stay stopped without a sign:

- When the server fails to start, the service now stops with an error (exit code 1067) and writes it to the `Duplicati 2` event log. Before, Windows saw a normal stop.
- The MSI sets recovery actions for the service: restart after 60 seconds, up to twice.

With this, the service should come back on its own a minute after a failure like yours. I tested this with a test service on Windows 11, but not with an installed MSI yet.

Why `System.IO.Compression` could not be loaded is still open. If you see it again, a list of the files in the install folder right after the failure, and whether a reboot was pending, would help.

## #7665

#7744 is merged and should be in the next canary. When a file uploaded in the same run is missing from the final listing, Duplicati now lists the destination again before it reports the file as missing. It uses the existing `--number-of-retries` (5 by default) and `--retry-delay` (10 seconds by default) options. `--number-of-retries=0` turns it off. A file that was already seen in an earlier listing and then disappears is still reported at once.

In your case the dlist showed up 4 seconds later, so the first new listing should find it. I could only test this with a test backend that hides the file, not with pCloud itself, so please tell us if it still happens after the update.
